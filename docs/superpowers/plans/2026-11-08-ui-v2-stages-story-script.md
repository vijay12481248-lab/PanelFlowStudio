# UI v2 Stage Rebuilds: Story and Script Implementation Plan (M5c)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the two largest narrative legacy screens (Story 1,006 lines, Script 1,028 lines) and their two helper components with v2 stages on the workbench frame, keeping every engine call and approval gate, fixing the id mismatches the real data exposed, and removing the stale and invented labels.

**Architecture:** Each stage is `features/stages/<name>/` with pure models (id normalisation, grouping, gates, validation lookups, job-activity wording) covered by unit tests, React Query hooks from the M5b kit (`useJob`, `useProjectJobs`), and v2 components. Editing flows (character edit, merge, split, script line edit, storyboard beat edit) are v2 `Dialog`s or inline forms with `Field` errors, never `reportError` for input mistakes. The M5b kit (`StageToolbar`, `ConfirmDialog`, `JobProgress`, `engineReason`/`refusal`, `useStageNav`, `stageData`) is reused as is.

**Tech Stack:** React 18, `@panelflow/ui-v2`, react-router 7, `@tanstack/react-query` 5, `tsx --test`, Playwright on installed Chrome. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-08-ui-v2-design.md` (section 6 "Workbench", section 7 row M5). Builds on M1 to M5b (done on `feat/ui-v2`). Open items: `docs/UI_V2_UNCOVERED.md`.

## Scope

- **In M5c:** Story (Narrative IR review) and Script (adaptation, validation, storyboard) stages; removal of `StoryReviewScreen`, `ScriptReviewScreen`, `StoryAnalysisActivity`, `StoryboardPreview` and their `onBack` wiring.
- **Deferred:** M5d Panels, OCR and Render; Narration Studio and the story editor (M7). The `ErrorContext` job/cancel machinery stays (other screens use it).
- **Facts from the code and the real data that shape this plan** (project `098c6713…`, read-only probes):
  - **Id mismatch.** `GET /characters` and `GET /scenes` return `id`, not `character_id` / `scene_id`; `canonical_name` is `null` for every character (names live in `display_name`). The narrative document (`GET /narrative`) does carry `character_id` and `scene_id`. The legacy screens read `scene.scene_id` from the scenes list, so by reading the code against the real field names (inferred, not run) the Scenes tab shows scenes with **no beats or events**, and `char.character_id` is `undefined` for edit, merge, split and the speaker list. The rebuild builds characters and scenes from the narrative document and normalises `id` as a fallback.
  - **Mock default.** Story analysis defaults to provider `mock` unless the project is "visual storytelling". The owner's rule is never to fall back silently to mock; the rebuild never preselects a mock provider and labels it "Test data only".
  - **Invented numbers and stale copy.** "Faithfulness coverage" shows `100%` when no validation report exists; a "Milestone 4 Boundary Guard" banner says voice generation is locked although the Audio stage exists. Both go; coverage says "Not checked".
  - **`validate` writes.** `POST /scripts/{id}/validate` recomputes and commits `quality_metrics`. It is idempotent and the legacy screen ran it on every load, so it still runs once when a script loads and after an edit, never in a loop, and never when no script exists.
  - **Real project has a storyboard but no script row** (`/script` is 404; the October database restore probably lost `scripts`). The Script stage must show the Generate invitation, not crash, and say nothing it cannot back up. No project in the app has a script, so the Script stage's editing flows can only be tested with synthetic data; say so in the report.
  - The real narrative has 204 utterances (many are OCR noise, speaker ids are character ids), 5 characters, 7 scenes, 11 beats, 13 events, 0 continuity warnings.
  - Ten per-line action buttons ("Regenerate", "Shorten", ... "Remove") sit in one row on every script line; "Remove" and "Merge next" act at once. They move into one menu and the destructive ones confirm.
- The engine, the owner's uncommitted YouTube files and `packages/api-client` are not edited.

## Global Constraints

- Semantic tokens only (the colour ratchet enforces it); sentence case, verb-first buttons; errors say what happened and what to do and never show a raw exception (`refusal` / `engineReason` from the kit); empty states invite an action; status is never colour alone. Rights gate and the owner's rules unchanged: nothing here weakens an approval gate.
- Every start, cancel, approve, merge, split, save, remove and regenerate guards against a fast double click with a synchronous ref and shows its busy state.
- No `window.confirm`, `window.alert` or `prompt`; no bare `console.error` swallowing of a failure: a failure is shown in words.
- Polling starts only while the stage is mounted and work is active, and stops on unmount (tests assert no further calls after cleanup). A job already running when the stage opens (story analysis, script generation) is followed, not restarted.
- Test commands: `npm run test:ui`, `cd apps/desktop && npx tsc --noEmit -p .`, `cd apps/desktop && npx playwright test`; run with `--tsconfig apps/desktop/tsconfig.json`; stage tests use `features/__tests__/pageHarness.tsx` (`mountPage`, `settle`, `press`, `clickTwice`, `setValue`, `setSelect`). Stub `api` methods on the shared `api` object as the M5b stage tests do.
- Commit only the files a task touches, with explicit paths. The owner's uncommitted files (`ProviderHealthModal.tsx`, `engine/youtube/*`, `packages/api-client/src/index.ts`, `engine/chronoflow/*`, and whatever else `git status` shows modified at the start) are never staged. Real-data checks only read and navigate: do not press Run or Re-analyze, Approve, Generate, Re-adapt, Validate, Save, Merge, Split, Remove or any line action on the owner's projects; say what was not exercised.
- Test-first for every behaviour; after a green run, mutate the guard or rule the test claims to protect and watch it fail (M5b found a hidden gap this way).
- Real data beats typed data: wherever a new model reads an engine field, the test fixture uses the real field names listed above, not only the `shared-types` shapes.

## Review Focus

1. **Ids.** Edit, merge, split, speaker reassignment and the beats under each scene use the right ids with the engine's real shapes (`id` only, `canonical_name: null`); a character with no id and no name is skipped, never sent as `undefined`. (Tasks 1, 3, 4)
2. **Gates.** Approve narrative stays blocked by unresolved ERROR continuity warnings and while analysis runs; Approve script is refused in words (and the report is refetched) when the engine refuses; neither moves on after a refusal and neither can be double-submitted. (Tasks 3, 6)
3. **No silent fallback.** No mock provider is preselected; with no healthy real provider the Run button is disabled and says why; a job already running is followed, not restarted; a lost connection is shown, not left spinning. (Tasks 2, 3, 6)
4. **Destructive and costly actions.** Re-analyze, Re-adapt, merge, remove line and merge-next line ask first; per-line actions and speaker changes cannot race each other or double-fire. (Tasks 3, 4, 7)
5. **Honest empty and failed states.** No narrative, no script (with a storyboard still present), no validation report ("Not checked"), a failed analysis, an unavailable panel image and a failed validation each show the reason and the next action. (Tasks 3, 6, 7)
