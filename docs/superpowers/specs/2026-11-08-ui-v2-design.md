## 1. Goal and success

One calm, rich, consistent desktop app. The owner opens it and finishes a day's work (review, fix, render, upload) without
hunting for buttons. Success means:

- Every screen sits in one shell with one navigation, one Settings area, one Jobs page.
- No duplicate entry points or duplicate implementations of the same concept.
- Every screen is built from the same tokens and primitives; no hard-coded colours in screens.
- The main journeys work by keyboard, have visible focus, readable contrast, and text you can select and copy.
- Anything the UI cannot do yet is written down in `docs/UI_V2_UNCOVERED.md`, not hidden behind a stub.

Non-goals: engine changes, new pipeline features, a mobile layout (the window must work down to about 1100 px wide;
below that it degrades gracefully but is not designed for).

Fixed rules that still apply (AGENTS.md): rights gate stays and UNKNOWN is refused; YouTube uploads are private by default and
public or scheduled needs explicit confirmation; local-first, no silent cloud fallback; verify on real data.

## 2. Audit findings (2026-11-08, real app against the live engine)

1. **Three shells.** Dashboard has its own rail; pipeline screens use a plain zinc top bar (brand line still says
   "AI-Assisted Motion Comic Ingestion & Production Engine"); Original Stories, Anime Review, ChronoFlow and the Story Editor are
   full-screen pages with a bare "Back" link and no navigation.
2. **State-enum routing.** `App.tsx` (693 lines) holds `currentScreen` in `useState`, threads `selectedProject` through props and
   passes about 20 `onOpenX` callbacks. No URLs, no browser back, no deep links.
3. **Duplicates.**
   - "Workspace health", "Tools & Models", "Model Settings", "Engine Settings", "Open Library" and the nav "Library" all open
     `ProviderHealthModal` (2,614 lines); "AI Providers" is a second implementation of the same concept.
   - Auto-Pilot appears in the header and again in the pipeline bar.
   - Four job-queue views: `JobQueueSidebar`, `MultiProjectQueueDashboard`, `JobActivityPanel`, `NarrationJobQueue`.
   - Image generation: `ComfyImageScreen` plus separate art paths in Original Stories and ChronoFlow.
   - `ProjectsScreen.tsx` is imported but never rendered (dead).
   - ChronoFlow is a separate static HTML app in an iframe (`engine/chronoflow/static`) with its own look.
4. **No design system.** 169 distinct hex colours in TSX; 945 indigo, 524 amber, 377 rose, 372 emerald utility uses;
   three competing brand blues (`#3b49df`, `#6366f1`, `#4f46e5`). `tailwind.config.js` is a copy of the Tailwind v3 palette, not a theme.
   `packages/ui` (1.8k lines) exists but screens hand-roll their own components. `body { user-select: none }` blocks copying
   OCR text and scripts.
5. **Layout problems.** At a narrow window the dashboard's three columns squeeze the content: project-card action buttons clip
   ("Files"), titles truncate. Original Stories is an unstyled admin form.
6. **Size and tests.** Files of 1.7k to 2.8k lines (`ContextualInspector`, `OCRReviewScreen`, `StoryEditorTimeline`,
   `NarrationStudio`, `PanelReviewScreen`). JS tests are `tsx --test` with `node:test` and jsdom; there are no end-to-end or
   visual tests and no CI.
7. **Possible missing wiring** (to confirm in M1): 35 of 230 `api-client` methods are not referenced by the desktop UI (render
   validation and profiles, `subscribeRenderEvents`, music take selection, `listBatchJobs`, YouTube channel and agent settings,
   `mergeScenes`, `harmonizeNarration`, `setConcurrencySettings`, `browseFilesystem`, ...). No dedicated screen found for the film
   pipeline, explainer batches or the upload kit.

## 3. Visual language: Midnight Glass

Deep navy world, translucent glass panels, one royal-blue accent, art-forward (project covers, panels and generated art are the
hero imagery). Glass and glow are used on hub screens; workbenches and editors stay flatter and denser.

### Tokens (CSS variables, exposed to Tailwind v4 through `@theme`)

| Group | Tokens (initial values) |
|---|---|
| Canvas | `--ink #070b1c`, `--navy #0c1433`, `--glow #1b2f7a` (page background is a radial gradient of these) |
| Surfaces | `--glass rgba(22,32,72,.55)`, `--glass-hi rgba(34,48,98,.62)`, `--surface-flat #101a3d` (workbench panels, no blur), `--edge rgba(150,175,255,.14)` |
| Text | `--text #eef1ff`, `--dim #9aa6d0`, `--faint #6a76a3` (all checked for 4.5:1 on their surface in M1) |
| Accent | `--accent #3b6bf5`, `--accent-soft rgba(59,107,245,.22)`; one filled accent control per view |
| Status | `--ok #46d6a3`, `--warn #f0b35a`, `--bad #f2667a`, `--info #7aa2ff` (status is never colour alone: icon or label too) |
| Shape | `--r-card 22px`, `--r-ctl 14px`, `--r-pill 999px` |
| Type | Display `Sora` (titles, hero), body `Geist`, data `Geist Mono` (timecodes, counts, ids); scale 12/13/14/16/20/30 |
| Motion | `--dur-fast 120ms`, `--dur-base 200ms`, `--ease-out`; all motion off under `prefers-reduced-motion` |
| Elevation | at most two floating layers on screen (popover, dialog); glow only on the active dock item and the primary button |

Fonts are bundled locally (no CDN at runtime; the app is local-first). The existing light-theme question is deferred: tokens are
semantic so a light "Paper" theme can be added later without touching screens.

### Rules
- Screens never use raw hex or palette utilities (`indigo-500`); only semantic tokens. A unit test greps for violations.
- Sentence case, verb-first buttons, errors say what happened and what to do (no raw exception text), empty states invite an action.
- `backdrop-filter` only on hub surfaces and only on surfaces that do not scroll large content (GPU is shared with ComfyUI and Ollama).
- Text is selectable everywhere except draggable chrome.

## 4. Architecture

### Packages
- `packages/ui` becomes the design system in three layers: `tokens` (CSS), `primitives` (Button, IconButton, Chip, GlassPanel,
  Surface, ListRow, Tile, Stepper, Dock, Tabs, Dialog, Drawer, Menu, Tooltip, Toast, Skeleton, EmptyState, ErrorState,
  Progress, Field/Input/Select/Switch) and `patterns` (PageHeader, InboxRow, JobCard, EngineStatus, ProjectHero).
- Old `redesigned-dashboard.tsx`, `enhanced-components.tsx` and the `Svg*` decoratives are removed when their last user migrates.
- `apps/desktop/src/app/` holds shell, routes, providers; `apps/desktop/src/features/<area>/` holds screens; `shared/` holds hooks.

### Routing
Hash routes (work inside Tauri without a server). The URL is the source of truth for project id and stage; the "selected project"
prop-drilling and `ScreenMode` enum are deleted. Legacy screens are wrapped in thin route components that load the project by id
and pass the same props they take today, so nothing is rewritten in M2.

### Data
One query cache for engine data (stale-while-revalidate, retries, polling intervals per query, request cancellation) replacing
per-screen polling. Engine health stays a single provider. The Home inbox is a client-side aggregation (`useInbox`) of data the
engine already serves; a dedicated `/inbox` endpoint is listed as an optional later improvement.

### New dependencies (each needs the owner's OK before install)
- `react-router` (nested layouts, params, loaders)
- Radix UI primitives (`dialog`, `dropdown-menu`, `tabs`, `tooltip`, `popover`, `switch`) for accessibility
- `cmdk` (command palette)
- `@tanstack/react-query` (data cache and polling)
- `@playwright/test` (dev only; flow and screenshot tests)
- Local font files (Sora, Geist, Geist Mono; open licences) copied into `apps/desktop/public/fonts`

## 5. Navigation and routes

Dock (six items, always the whole top level): **Home, Projects, Create, Jobs, Library, Settings**. Ctrl K opens a palette that
searches projects, screens, actions ("Open anime review", "Retry failed job") and settings.

| Route | Replaces | Type |
|---|---|---|
| `/home` | dashboard (`DashboardShell` panels) | Hub (inbox) |
| `/projects`, `/projects/:id` | project grid, `DashboardProjectCard`, `handleOpenProject` stage routing | Hub / project overview |
| `/projects/:id/:stage` with stage in `acquire, pages, panels, ocr, story, script, audio, motion, render, publish` | `AcquisitionScreen`, `PageReviewScreen`, `PanelReviewScreen`, `OCRReviewScreen`, `StoryReviewScreen`, `ScriptReviewScreen`, `AudioScreen`, `MotionScreen`, `RenderScreen`; `publish` is new and wraps packaging and the upload kit | Workbench |
| `/editor/:id` | `StoryEditorScreen` | Editor |
| `/create`, `/create/new`, `/create/stories`, `/create/anime`, `/create/chronoflow`, `/create/image` | `NewProjectScreen`, `OriginalStoriesScreen`, `AnimeReviewScreen`, `ChronoFlowScreen`, `ComfyImageScreen` | Studio |
| `/jobs` | `JobQueueSidebar`, `MultiProjectQueueDashboard`, `JobActivityPanel`, `NarrationJobQueue` | Hub |
| `/library/audio`, `/library/images` | `AudioLibrary`, `AIMusicStudio`, asset browsers | Hub |
| `/settings/engine`, `/settings/models`, `/settings/providers`, `/settings/youtube`, `/settings/diagnostics` | `ProviderHealthModal`, `ProviderManagementScreen`, YouTube card in Original Stories | Settings |

Auto-Pilot is one action in the project header. Errors use the existing `ErrorContext`, surfaced as toasts and the Jobs page.

## 6. Screen types

- **Hub** (Home, Projects, Jobs, Library): glass, art-forward, generous space.
- **Workbench** (pipeline stages): top project header and stage stepper (shows stale and blocked stages), then list or filmstrip on
  the left, canvas in the middle, inspector on the right. Flat panels, dense, keyboard-first.
- **Studio** (Create): a guided start (what do you want to make?) above a queue of what is running.
- **Editor**: full width, dock auto-hides, its own toolbar; shares tokens and primitives.
- **Settings**: section list plus detail pane; engine, models and providers are sections of one area.

## 7. Milestones

Each milestone leaves the app usable, ends with type check, unit tests, a check in the real app against the live engine with
screenshots, and a short note of what was not verified. Per AGENTS.md each milestone is its own commit (only its files).

| # | Milestone | Done when |
|---|---|---|
| M0 | Owner approves dependency list; spec and plan approved | install allowed |
| M1 | Tokens, fonts, primitives; `docs/UI_V2_UNCOVERED.md`; no-raw-hex test | every primitive renders in all its states on a dev gallery route; contrast checked; API-client usage audit written |
| M2 | New shell: router, dock, top bar, palette, providers; every legacy screen mounted via route wrappers | all old screens reachable by URL and dock/palette; back and forward work; old shells and duplicate buttons removed |
| M3 | Home inbox, Projects, Jobs | inbox shows real engine data; the four queue views are deleted |
| M4 | Settings: engine, models, providers, YouTube, diagnostics | `ProviderHealthModal` and `ProviderManagementScreen` replaced; seven entry points become one |
| M5 | Workbench stages (acquire to render, then publish) | one stage layout; stepper shows stale and blocked; Auto-Pilot in header only |
| M6 | Create studios: new project, stories, anime, ChronoFlow, image | all in shell; ChronoFlow iframe app uses the same tokens |
| M7 | Editors: Story Editor, narration, audio library | shared tokens; large files split where touched |
| M8 | Hardening | axe-style accessibility pass, keyboard journeys, `user-select` fix, 1100 px layout, dead code removed, Playwright flows green |

Order inside M5 to M7 follows how often each screen is used.

## 8. Quality gates

- Unit tests with `tsx --test` for: route table, `useInbox` aggregation, stage-to-route mapping (replaces `handleOpenProject`),
  no-raw-hex rule, token contrast pairs.
- Playwright (after approval) for: open a project to its right stage, approve a stage, retry a failed job, change a setting,
  command palette. Screenshots of Home, a workbench stage and Settings at 1440x900 and 1100x700.
- Manual check in the browser pane against the live engine before each milestone is called done; anything unverified is stated.
- Performance: measure frame time on Home with glass on while ComfyUI is generating; if it drops, reduce blur.
- Accessibility: visible focus on all controls, 4.5:1 text contrast, status not by colour alone, reduced motion respected,
  dialogs trap and restore focus (via Radix).

## 9. Risks

- Glass blur competes with ComfyUI and Ollama for the GPU: limited to hub surfaces and measured in M3.
- Wrapping legacy screens first means some screens look old inside the new shell until their milestone; accepted.
- Splitting 2k-line screens risks regressions: split only when the screen is migrated, keep existing tests green.
- Tauri window behaviour of hash routing and fonts is verified in the dev server first; "opening the desktop UI in a real window"
  is still listed as not done in AGENTS.md and is checked in M2.

## 10. Uncovered areas (initial list; the file `docs/UI_V2_UNCOVERED.md` is created in M1 and kept current)

- Film pipeline, explainer batches, upload kit: engine features with no dedicated UI found.
- Shorts (vertical cut) and channel watermark: not built anywhere.
- Music takes (`listProjectMusicTakes`, `selectMusicTake`, `saveProjectMusicPlan`), render validation and profiles, render event
  subscription, batch job listing, concurrency settings: API methods with no UI caller (confirm each in M1).
- Single `/inbox` endpoint: optional engine improvement; inbox is aggregated client-side for now.
- Light theme ("Paper"): deferred.
